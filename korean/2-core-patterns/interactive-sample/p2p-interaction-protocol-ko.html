프로토콜 버전 3

인터랙티브 레슨 P2P 동기화 프로토콜

두 참여자가 같은 레슨을 열었을 때 입력, 선택, 문장 재배열, 공동 미션 완료 상태와 지금 보고 있는 페이지를 전달하기 위한 문서이다. WebRTC DataChannel 등 실제 전송 수단과 독립적인 애플리케이션 레벨 규약을 정의한다.

적용 샘플: sample-lesson-interactive.html · trial-1-hangul.html

1. 기본 원칙

동기화는 허용 목록 방식이다. data-sync="shared"가 명시된 대상만 상대방에게 전송한다. 표시가 없거나 data-sync="local"인 대상은 로컬 전용이다.
  1. 각 공유 대상은 문서 안에서 유일한 data-sync-id를 가져야 한다.
  2. ID는 DOM 순서나 표시 문구가 아니라 활동의 의미를 나타내는 영문 kebab-case로 작성한다.
  3. 마우스 좌표나 원시 클릭을 보내지 않고, 변경된 의미 상태를 보낸다.
  4. 정답, 오답 애니메이션, 포커스 같은 파생 UI는 전송하지 않고 각 브라우저에서 계산한다.
  5. 원격 상태를 적용하면서 같은 메시지를 다시 보내지 않는다.

2. HTML 표시 규약

속성필수 여부의미
data-sync="shared" 공유 대상에 필수 이 대상의 의미 상태를 P2P 채널로 전송한다.
data-sync="local" 선택 로컬 전용임을 문서에 명시한다. 생략한 경우도 기본값은 local이다.
data-sync-id 공유 대상에 필수 두 브라우저가 같은 대상을 찾는 안정적인 식별자다.
data-option-id 선택형 활동에 필수 공유 선택 그룹 안에서 각 선택지를 식별한다.
data-item-id 재배열 활동에 필수 공유 재배열 그룹 안에서 각 칩을 식별한다.
data-page-id 페이지 이동에 필수 .phone의 직계 자식인 각 페이지를 식별한다. 버전 2에서 추가.
data-sync-id와 data-page-id는 소문자 kebab-case (^[a-z0-9][a-z0-9-]*$)로 제한한다. 규칙 §1.2를 강제하는 동시에, 수신한 문자열이 선택자로 들어가기 전의 방어선 역할을 한다.

텍스트 입력

<span
  class="slot"
  data-sync="shared"
  data-sync-id="p1-fill-book-particle"
>을</span>

샘플 레슨은 실행 시 .slot과 .answer-space를 실제 input 또는 textarea로 바꾼다. 이때 동기화 속성을 생성된 컨트롤로 이전하여 런타임에 같은 data-sync-id가 중복되지 않게 한다.

선택형 활동

<div class="choose-row"
  data-sync="shared"
  data-sync-id="p1-choice-rice-particle">
  <span class="opt" data-option-id="eul">을</span>
  <span class="opt" data-option-id="reul">를</span>
</div>

문장 재배열

<span class="answer-space"
  data-sync="shared"
  data-sync-id="p1-reorder-bread">저는 빵을 좋아해요</span>

<span class="choice" data-item-id="bread">빵을</span>
<span class="choice" data-item-id="like">좋아해요</span>
<span class="choice" data-item-id="subject">저는</span>

선택 묶음 (복수 선택)

「ㅏ가 들어간 블록을 모두 누르세요」처럼 한 묶음에서 여러 개를 고르는 활동이다. 묶음 전체가 하나의 공유 대상이고, 페이로드는 지금 눌려 있는 선택지의 집합이다. 정답·오답 표시는 data-ok에서 각자 계산한다(§1.4). 

<div class="tap-grid"
  data-sync="shared"
  data-sync-id="tiles-find-the-vowel">
  <button class="tap-tile" data-ok="1" data-option-id="나">나</button>
  <button class="tap-tile"            data-option-id="머">머</button>
  <button class="tap-tile" data-ok="1" data-option-id="나-2">나</button>
</div>

한 묶음 안에서 같은 글자가 반복되면 뒤쪽에 -2, -3을 붙여 구분한다. 위치가 아니라 글자 자체가 식별자다.

글자 조립

자음과 모음을 눌러 글자를 만드는 활동이다. 조립기 하나가 공유 대상이고, 페이로드는 그 조립기의 의미 상태 — 완성된 칸, 지금 작업 중인 칸, 아직 반만 고른 자음·모음 — 이다. 칸은 순번이 아니라 그 칸이 요구하는 글자로 식별한다. 

<div class="builder"
  data-sync="shared"
  data-sync-id="builder-build-the-block"
  data-answers="노,마,미">…</div>

페이지 이동

페이지 넘김은 덱 전체가 하나의 공유 대상이다. 수업 중 두 화면이 서로 다른 페이지를 보고 있으면 나머지 동기화가 의미를 잃기 때문에, 이동은 local이 아니라 shared다. 대상은 페이저 자체이고 각 페이지는 data-page-id를 가진다. 

<nav class="pager"
  data-sync="shared"
  data-sync-id="deck-page">…</nav>

<div class="section" data-page-id="p1-reorder">…</div>

규약은 대칭이다. 진행자와 학습자를 구분하지 않고, 양쪽 모두 페이지를 넘길 수 있으며 충돌은 §6의 일반 규칙으로 해소한다. 스크롤 보기에서 화면에 걸린 페이지가 바뀌는 것도 같은 이동으로 취급해서 보낸다. 그렇지 않으면 한쪽이 보기 모드를 바꾸는 순간 조용히 어긋난다.

3. 메시지 봉투

모든 메시지는 UTF-8 JSON 객체이며 다음 공통 필드를 사용한다.

{
  "protocol": "podo.lesson-sync",
  "version": 3,
  "type": "interaction",
  "lessonId": "core-patterns-2",
  "contentVersion": "2026-07-23",
  "senderId": "peer-a",
  "sequence": 42,
  "logicalTime": 108,
  "targetId": "p1-fill-book-particle",
  "action": "set-value",
  "payload": {
    "value": "을",
    "committed": false
  }
}
필드설명
protocol항상 podo.lesson-sync.
version이 문서의 메시지 버전. 현재 값은 3.
lessonId열려 있는 레슨의 영구 식별자. HTML의 <meta name="podo:lesson-id">에서 읽는다.
contentVersion양쪽 HTML 구조가 호환되는지 확인하는 콘텐츠 버전.
senderId세션 안에서 유일한 피어 식별자.
sequence송신자별 단조 증가 번호. 중복 및 역순 메시지 제거에 사용.
logicalTime충돌 해결용 Lamport 논리 시각.
targetIdHTML의 data-sync-id와 일치하는 값.
action대상 유형에 맞는 의미 동작.
payload동작에 필요한 최소 상태.

4. 동작별 페이로드

활동actionpayload
입력/텍스트 영역 set-value {"value":"커피를 좋아해요","committed":false}
선택형 문제 select-option {"optionId":"eul"}
문장 재배열 set-order {"itemIds":["subject","bread","like"]}
공동 미션 set-checked {"checked":true}
선택 묶음 (복수 선택) set-selection {"optionIds":["나","마"]}
글자 조립 set-build {"done":["노"],"active":"마","c":"ㅁ","v":null}
페이지 이동 set-page {"pageId":"p1-reorder","pageIndex":8}

set-selection은 눌린 것만 담은 전체 집합이다. 하나를 더 누르든 취소하든 항상 현재 집합 전부를 보내므로, 메시지 하나를 놓쳐도 다음 메시지에서 상태가 맞춰진다.

set-build의 done은 완성된 칸이 요구하는 글자들, active는 지금 작업 중인 칸(전부 끝났으면 null), c·v는 아직 글자가 되지 못한 자음·모음이다. 완성 여부는 받은 쪽에서 다시 계산하지 않고 done을 그대로 신뢰한다 — 「눌러서 다시 하기」로 이미 맞춘 칸을 되돌릴 수 있어, 정답 여부만으로는 복원할 수 없는 이력이기 때문이다.

텍스트의 input 이벤트는 50~100ms 단위로 조절해서 보낼 수 있다. blur 또는 Enter 시에는 committed: true인 최종 메시지를 즉시 보낸다. IME 조합 중에는 전송을 보류하고 compositionend 뒤에 보낸다.

set-page의 기준은 pageId다. pageIndex는 로그와 표시용 참고값이며, 두 값이 어긋나면 pageId를 따른다. 문서에 없는 pageId는 무시한다.

5. 송수신 처리

송신

  1. 이벤트 대상에서 가장 가까운 [data-sync] 요소를 찾는다.
  2. data-sync가 shared가 아니면 종료한다.
  3. 활동 유형에 따라 현재 값을 의미 동작으로 직렬화한다.
  4. 논리 시각과 송신자별 sequence를 증가시키고 채널로 보낸다.

수신

  1. 프로토콜, 버전, lessonId, contentVersion을 검증한다.
  2. 중복되었거나 이미 처리한 sequence라면 무시한다.
  3. [data-sync="shared"][data-sync-id="…"] 대상이 정확히 하나인지 확인한다.
  4. 대상 유형과 action/payload 조합을 검증한 뒤 상태를 적용한다.
  5. 기존 채점 함수를 실행하여 correct, wrong, readOnly 등의 UI를 로컬에서 다시 계산한다.
let applyingRemote = false;

function applyRemote(message) {
  applyingRemote = true;
  try {
    // 검증 후 값/선택/순서/체크 상태를 직접 적용한다.
    // 필요할 때 채점 함수를 명시적으로 호출한다.
  } finally {
    applyingRemote = false;
  }
}

function onLocalInteraction(event) {
  if (applyingRemote) return; // 에코 루프 방지
  // shared 대상만 직렬화하여 전송한다.
}

6. 충돌 및 초기 상태

  • 대상별로 마지막 적용 버전 (logicalTime, senderId)를 저장한다. logicalTime이 큰 변경을 우선하고, 같으면 senderId 문자열 비교로 결정한다.
  • 접속한 피어는 snapshot-request를 보낸다. 이미 접속한 피어는 모든 공유 대상의 현재 의미 상태와 각 대상 버전을 담은 state-snapshot으로 응답한다.
  • 스냅샷을 적용한 뒤 도착한 더 최신 interaction 메시지는 정상적으로 이어서 적용한다.
  • lessonId 또는 contentVersion이 다르면 상태를 적용하지 않고 버전 불일치를 표시한다.

7. 로컬로 유지하는 상태

  • 정답 보기/숨기기 버튼과 정답 캡션. 이건 진행자용이고, 보내면 학습자에게 그 페이지의 답을 전부 넘겨주는 것과 같다. 절대 공유하지 않는다.
  • 보기 모드(한 장씩 / 스크롤). 같은 페이지를 각자 편한 방식으로 보면 된다.
  • 포커스, 커서 위치, 텍스트 선택 영역, hover, 페이지 안에서의 스크롤 위치
  • 일시적인 오답 흔들림 애니메이션
  • 정답에서 계산되는 correct, wrong, dim, readOnly
  • 레슨 마지막의 개인 자기평가 체크리스트
스크롤 위치는 로컬이지만 어느 페이지를 보고 있는가는 공유다(§2 페이지 이동). 스크롤 보기에서 화면에 걸린 페이지가 바뀌면 set-page를 보내고, 페이지 안에서의 스크롤 양은 보내지 않는다.

위 상태를 나중에 공유해야 한다면 기존 기본값을 바꾸지 말고 해당 요소에 명시적인 shared ID와 새로운 의미 action을 추가한다.

8. 검증 및 보안 제한

  • 수신 targetId가 실제 shared 허용 목록에 없으면 무시한다.
  • 수신 문자열은 텍스트 값으로만 적용하며 innerHTML이나 eval에 전달하지 않는다.
  • 텍스트 길이는 대상별 상한을 둔다. 이 샘플의 권장 상한은 2,000자다.
  • optionId와 itemIds는 해당 그룹의 HTML에 선언된 값만 허용한다.
  • 재배열 itemIds에 중복 또는 선언되지 않은 값이 있으면 전체 변경을 거부한다. 다만 부분 배열은 정상 상태다 — 칩은 하나씩 놓이므로 아직 pool에 남은 칩이 있는 중간 상태가 존재한다. 선언된 집합의 부분집합이면 받아들이고, 메시지에 없는 칩은 pool로 되돌린다. (버전 1은 완성된 배열만 가정해서 이 경우를 거부했다.)
  • set-page의 pageId는 문서에 실제로 있는 data-page-id여야 한다. 없으면 무시한다.
  • 메시지 크기와 전송 빈도를 제한하여 비정상 피어가 UI를 과부하시키지 못하게 한다.

9. 샘플 구현 범위

동봉된 레슨은 HTML 식별자, shared/local 분류, 선택지/재배열 항목 ID, 동적 입력으로의 메타데이터 이전에 더해, §3~§8의 봉투 구성·검증·충돌 해소·스냅샷까지 구현한다. DataChannel 생성과 세션 협상만 호스트 애플리케이션의 몫이다. 전송 계층은 다음 두 지점에만 붙이면 된다. 

PodoLessonSync.configure({ senderId: 'peer-a' });
PodoLessonSync.onOutbound(msg => channel.send(JSON.stringify(msg)));
channel.onmessage = e => PodoLessonSync.receive(JSON.parse(e.data));

// 접속 직후
PodoLessonSync.requestSnapshot();

PodoLessonSync.snapshot()은 현재 모든 공유 대상의 의미 상태를 돌려주며, snapshot-request를 받으면 자동으로 state-snapshot으로 응답한다.
